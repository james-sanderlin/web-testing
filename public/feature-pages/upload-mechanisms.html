Upload Mechanisms

Enumerates the distinct browser mechanisms a page can use to get file data from the user (or from script) into JS-land. Each card isolates one API surface so you can test upload interception, DLP, or extension hooks against each path independently.

input.files

BUTTONDRAG & DROP

Click for the native picker, or drop a file directly onto the input — both populate .files and fire the same change event.

input.files (capture)

BUTTONDRAG & DROP

Same input as above, but accept="image/*" capture hints mobile browsers to open the camera directly instead of a generic file browser.

input.files (webkitdirectory)

BUTTON

The webkitdirectory attribute lets the user pick a whole folder; each file carries a webkitRelativePath.

dataTransfer.files

DRAG & DROP

Reads event.dataTransfer.files on drop — the most common drag/drop pattern.

Drop a file here

dataTransfer.items

DRAG & DROP

Alternate read path: iterate DataTransferItemList and call item.getAsFile() instead of reading .files.

Drop a file here

webkitGetAsEntry() (folder)

DRAG & DROP

Drop a folder. Uses webkitGetAsEntry() + FileSystemDirectoryReader to recursively read nested structure — the only path that isn't a flat file list.

Drop a folder here

clipboardData.files

CLIPBOARD

Copy a file or image, click the box, then paste (Ctrl/Cmd+V). Reads event.clipboardData.files from the paste event.

Click here, then paste (Ctrl/Cmd+V)

navigator.clipboard.read()

BUTTONCLIPBOARD

Reads the OS clipboard directly on a button click — no paste event needed. Copy an image first, then click.

showOpenFilePicker()

BUTTON

Modern async picker that returns FileSystemFileHandles instead of a FileList.

showDirectoryPicker()

BUTTON

Grants a FileSystemDirectoryHandle for a whole folder, enumerable asynchronously including nested subfolders.

new File()

No user gesture at all — script constructs a File in memory and hands it to the same upload code (e.g. FormData + fetch) as a real selection.
