Upload Mechanisms

Enumerates the distinct browser mechanisms a page can use to get file data from the user (or from script) into JS-land. Each card isolates one API surface so you can test upload interception, DLP, or extension hooks against each path independently.

UM-01

input.files

BUTTONDRAG & DROP

The core file-input mechanism: reading the .files property off an <input type="file"> when its change event fires — whether that came from the native picker or a file dropped directly onto the input. The variants below are the same mechanism; they only change what the picker is constrained to.

2 more variants (capture, webkitdirectory)
accept="image/*" capture — hints mobile browsers to open the camera directly
webkitdirectory — lets the user pick a whole folder; each file carries a webkitRelativePath
UM-02

dataTransfer

DRAG & DROP

Reads event.dataTransfer.files on drop — the most common drag/drop pattern. The variants below read the same drop event's dataTransfer object through a different property/method.

Drop a file here
2 more variants (items, webkitGetAsEntry)
dataTransfer.items + item.getAsFile() — iterate the DataTransferItemList instead of reading .files directly
Drop a file here
item.webkitGetAsEntry() — drop a folder; recursively reads nested structure via FileSystemDirectoryReader, the only path that isn't a flat file list
Drop a folder here
UM-03

clipboardData.files

CLIPBOARD

Copy a file or image, click the box, then paste (Ctrl/Cmd+V). Reads event.clipboardData.files from the paste event.

Click here, then paste (Ctrl/Cmd+V)
UM-04

navigator.clipboard.read()

BUTTONCLIPBOARD

Reads the OS clipboard directly on a button click — no paste event needed. Copy an image first, then click.

UM-05

showOpenFilePicker()

BUTTON

Modern async picker that returns FileSystemFileHandles instead of a FileList. The variant below is the same File System Access API, returning a directory handle instead.

1 more variant (showDirectoryPicker)
showDirectoryPicker() — grants a FileSystemDirectoryHandle for a whole folder, enumerable asynchronously including nested subfolders
UM-06

new File()

No user gesture at all — script constructs a File in memory and hands it to the same upload code (e.g. FormData + fetch) as a real selection.
