Download Mechanisms

Enumerates the distinct browser mechanisms a page can use to push file data out of JS-land and onto disk. Each card isolates one API surface so you can test download interception, DLP, or extension hooks against each path independently. (For coverage of different file types being downloaded, see the Download and Download Headers pages instead.)

DM-01

<a download>

ANCHOR

A plain same-origin link with a download attribute. The browser saves the file instead of navigating, no script involved at all.

Download sample.csv
DM-02

Blob + createObjectURL

SCRIPT

fetch() the bytes, wrap them in a Blob, mint an object URL, and click a synthetic <a download> pointing at it — the common "export this data as a file" pattern.

DM-03

window.location.href

SCRIPT

Script navigates the top-level document straight at an attachment URL. No anchor element exists in the DOM at all — the server's Content-Disposition: attachment header is what turns the navigation into a save.

DM-04

window.open()

SCRIPT

Opens the attachment URL in a new tab/window. Some popup blockers and extensions treat this path differently from a same-tab navigation or an anchor click.

DM-05

Form submission

FORM

A real (hidden) HTML <form> submitted with method="GET". Some legacy download flows and file-export buttons use a form POST/GET instead of a plain link so they can send extra parameters.

DM-06

Hidden <iframe>

SCRIPT

Sets an invisible iframe's src to the attachment URL. The download fires without any navigation or new tab visible on the page — a classic technique for "download without leaving this page."

DM-07

data: URI

ANCHOR

A download-attributed link whose href is a base64 data: URI — the file content is embedded directly in the page, no network request at all.

Download data: URI
DM-08

Service Worker response

SW

Registers a service worker that intercepts a same-origin fetch and fabricates the response entirely in the worker (with its own Content-Disposition header) — no real network round trip. Tests whether download interception happens above or below the SW layer.
